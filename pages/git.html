Wprowadzenie do Gita

Git to rozproszony system kontroli wersji, który pozwala śledzić zmiany w kodzie źródłowym, ułatwiając współpracę nad projektami programistycznymi oraz zarządzanie historią rewizji.

Procedura pracy (Workflow)

  1. Synchronizacja: Pobranie najnowszych zmian z repozytorium zdalnego.
  2. Branch: Utworzenie i przełączenie na nową gałąź roboczą dla danej funkcji lub poprawki.
  3. Zmiana: Modyfikacja plików w projekcie.
  4. Commit: Zatwierdzenie zmian lokalnie wraz z opisem.
  5. Push: Wysłanie gałęzi do repozytorium zdalnego.
  6. PR (Pull Request): Utworzenie zgłoszenia połączenia kodu w celu code review i scalenia.

Zestawienie poleceń Git

Polecenie Opis działania
git clone Pobiera istniejące repozytorium zdalne na dysk lokalny.
git status Wyświetla status aktualnego drzewa roboczego i śledzonych plików.
git add Dodaje zmiany do obszaru śledzenia (staging area).
git commit Tworzy trwały punkt kontrolny (commit) z zatwierdzonymi zmianami.
git push Wysyła lokalne commity do repozytorium zdalnego.
git pull Pobiera zmiany ze zdalnego repozytorium i łączy je z bieżącą gałęzią.
git fetch Pobiera metadane i zmiany ze zdalnego repozytorium bez ich scalania.
git branch Tworzy, wyświetla lub usuwa gałęzie (branch).
git switch Bezpiecznie przełącza pomiędzy gałęziami projektu.
git log Wyświetla historię commitów dla bieżącej gałęzi.
